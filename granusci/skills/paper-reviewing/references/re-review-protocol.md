# 二轮审稿协议（re-review）

移植自 academic-paper-reviewer 的 re-review mode，适配 GranuSci 的两轮审稿门。

## 为什么二轮要换模式

第一轮是"全面评审"——所有维度、所有失败模式都过一遍。第二轮若仍然全面评审，
会产生两个问题：①审稿人注意力被新的次要问题分散，第一轮的核心问题反而没
被验证修复；②对作者不公平——按第一轮意见改的内容引出了新的全面审查。

第二轮的唯一职责：**验证第一轮意见是否被解决**。

## 协议

### 输入
- 第一轮的完整审稿意见（critical_issues + suggestions + feedback）
- 修改后的稿件

### 流程
1. **逐条建修复追踪表**：对第一轮每条 critical_issue，判定：
   - 已解决（指出修复证据位置）
   - 部分解决（指出剩余缺口）
   - 未解决
   - 变相回避（删掉了问题段落而非修复问题——按未解决处理并标注）
2. **修复副作用检查**：修复动作引入的新问题（如删数值导致新的一致性
   断层、改措辞导致新的过度声明）——只有这类"新问题"可以在第二轮提出。
3. **不重开的领域**：第一轮未提出且与修复无关的问题，第二轮不再提。
   （预防审稿轮次通胀——改一版冒出全新一批意见，永远收敛不了。）

### 判定标准
- 全部 critical_issues 已解决 且 无修复副作用 → pass=true
- 任一 critical_issue 未解决/变相回避 → pass=false，feedback 只含未解决项
- 全部已解决但有修复副作用 → pass=false，feedback 只含副作用项

### 输出格式
在标准 JSON 上追加：
"fix_tracker": [{"issue": "第一轮问题摘要", "status": "resolved|partial|unresolved|dodged",
                 "evidence": "修复证据位置或缺口说明"}]
